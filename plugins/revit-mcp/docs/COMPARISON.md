# Сравнение MCP-серверов для Revit

Разбор семи серверов из офлайн-набора и собственного сервера `revit-mcp` из этого репозитория.
Цель — Revit 2025–2027, клиенты Claude Code и Claude Desktop, рабочая станция без интернета.

**Как получены данные.** Исходники семи проектов прочитаны по состоянию репозиториев на 15.11.2026
(версии из набора). Ни один из семи серверов **не запускался** — ни здесь, ни в Revit: в таблицах то,
что написано в коде, установщиках и документации. Собственный сервер собран и проверен тестами без
Revit (подробности — в конце).

## По каждому серверу

### Horizun 4.0.0
- **Сильные стороны.** Самый зрелый по инженерии: CI на Windows и Linux, CodeQL, два тестовых проекта,
  отчёт о живом запуске в Revit 2027. Канал только для текущего пользователя. По умолчанию модель видит
  14 инструментов, остальные подключаются по запросу — это экономит контекст. Запись идёт в три шага с
  повторным чтением результата. Установка в профиль пользователя без прав администратора.
- **Слабые стороны.** Очень большой объём (125 инструментов, около 200 скриптов), часть документации на
  испанском. Сборка 4.0.0, судя по репозиторию, не подписана. Есть необязательные облачные функции
  (APS, Power BI, Application Insights) — по умолчанию выключены, полностью это не проверялось.

### BIMwright rvt-mcp 1.2.2
- **Сильные стороны.** Официальный MCP SDK, около 2600 тестов, документация на четырёх языках,
  самодостаточный exe. Режим `--read-only` (102 инструмента), привязка записи к конкретному документу.
- **Слабые стороны.** Выполнение произвольного C# внутри Revit включено по умолчанию. Установщик
  включает весь каталог (242 инструмента) — большой расход контекста и хуже выбор инструмента моделью.
  Плагин-подключение в этом репозитории запускает сервер с `--disable-send-code`.

### AEC Model Bridge 1.4.0
- **Сильные стороны.** Самая строгая модель записи: каждое изменение — план, который человек одобряет
  в панели Revit; одобрение одноразовое и привязано к аргументам. Есть режим без Revit для пробы.
- **Слабые стороны.** Авторы сами пишут, что ни одна версия Revit не проверена вживую, а Claude Code
  не тестировался. GPL. Тяжёлые зависимости (ifcopenshell, specklepy, anthropic). В старом режиме
  (`MCP_REVIT_LEGACY_PORT=1`) порт 3000 без аутентификации. Установщик пишет отдельную запись на каждый
  год Revit, что умножает число инструментов.

### RevitCortex 1.0.25
- **Сильные стороны.** Самый широкий охват предметных областей: арматура, металл, IFC, спецификации,
  Power BI. Произвольный код выключен по умолчанию.
- **Слабые стороны.** TCP-порт 8080 без токена. Установщик повышает права, предлагает исключение для
  Защитника Windows, при отсутствии Git качает его из интернета, сам правит настройки клиентов.
  Проверка обновлений при каждом запуске, канал обновлений через OneDrive. В коде заготовка
  лицензирования; исходники выпускаемых сборок ведутся в закрытом репозитории. CI нет.
  Для станции без интернета это самый неудобный вариант.

### s81 Autodesk--mcp 0.3.1
- **Сильные стороны.** Маленький и аккуратный: канал + токен, политика проверяется внутри Revit,
  тесты на канал, токен, тайм-ауты; CI собирает все 12 вариантов надстройки. Честный раздел «что
  проверено, а что нет». Ничего не ставит, кроме себя. Заодно работает с AutoCAD.
- **Слабые стороны.** Мало инструментов (12 для Revit). Запись и выполнение произвольного C# включены
  по умолчанию — выключаются в `config.json`.

### Demolinator
- **Сильные стороны.** Простой код на Python, легко читать и дописывать; работает через pyRevit,
  отдельная надстройка не компилируется.
- **Слабые стороны.** Порт pyRevit Routes без аутентификации. Произвольный IronPython без каких-либо
  ограничений. Нет разметки «чтение/запись», нет подтверждений. IronPython 2.7, закреплена старая
  версия MCP SDK. Самая длинная ручная установка (pyRevit, Python, 28 пакетов).

### KenLP 0.8.43
- **Сильные стороны.** Нацелен ровно на Revit 2025–2027 (.NET 8 и .NET 10 в явном виде), CI собирает
  все три. Нет произвольного кода. Предпросмотр изменений, журнал изменений, повторное чтение после
  записи, профили инструментов через переменную окружения. Только loopback, токен на каждый запуск.
- **Слабые стороны.** Один автор и большая поверхность (около 100 инструментов). Нужен Node.js и 91
  npm-пакет. Для каждой версии Revit свой порт и отдельная запись сервера.

## Рекомендация

1. **Основной готовый сервер — KenLP 0.8.43.** Он единственный из набора рассчитан именно на
   Revit 2025–2027, не содержит произвольного выполнения кода, имеет предпросмотр и журнал изменений.
   Плата — Node.js и npm-кэш, которые в наборе уже есть.
2. **Если нужен максимум возможностей — Horizun 4.0.0.** Лучшая инженерная культура и безопасная
   связь с Revit; произвольный Python выключен, пока вы сами его не включите. Ставится без зависимостей.
3. **Собственный `revit-mcp`** — когда важны обозримость и контроль: 23 инструмента, код целиком
   читается за вечер, запись выключена до явного включения, произвольного кода нет вовсе, зависимостей
   нет. Его разумно развивать под свои задачи (например, под выгрузку расчётных схем), но до первой
   проверки в живом Revit считать экспериментальным.
4. **Не рекомендую для этой задачи:** RevitCortex (порт без токена, установщик с повышением прав и
   обращениями в сеть), Demolinator (порт без аутентификации и неограниченный код), AEC Model Bridge
   (не проверен вживую, GPL). BIMwright и s81 пригодны, если сразу отключить выполнение кода.

**Ставьте один сервер за раз.** Несколько надстроек в одном Revit работать могут, но каждый
подключённый сервер добавляет свои инструменты в контекст модели, и одинаковые по смыслу инструменты
разных серверов мешают выбору.

Официальный сервер Autodesk (Revit 2027.2, Read-Tools Technical Preview) в наборе отсутствует и здесь
не рассматривался; он только читающий.

## Чем отличается собственный сервер

| Решение | Почему |
| --- | --- |
| Именованный канал только текущего пользователя + токен из файла обнаружения | Никаких сетевых портов: к Revit не подключится ни другой пользователь, ни страница в браузере |
| Запись выключена по умолчанию, включается кнопкой на ленте Revit | Решение принимает человек в Revit; клиент обойти его не может — проверка внутри надстройки |
| Нет инструмента выполнения произвольного кода | Убирает самый опасный класс ошибок и атак через подставленные инструкции |
| Удаление по умолчанию — пробный прогон | Revit удаляет зависимые элементы; сначала показывается, сколько их |
| Каждое изменение — одна транзакция «MCP: …» | Отмена одним Ctrl+Z; предупреждения Revit возвращаются в ответе, а не всплывают окнами |
| Сервер на Node.js без единой зависимости | Плагин работает сразу после установки из git, без `npm install` и без интернета |
| Все длины в миллиметрах, имена полей с суффиксом `Mm` | Модель не путает футы внутреннего представления Revit с единицами проекта |

### Что проверено, а что нет

Проверено здесь (Linux, без Revit):
- надстройка компилируется без предупреждений против справочных сборок Revit API 2025.4, 2026.4 и 2027.3
  (.NET 8 и .NET 10);
- 16 тестов сервера проходят, включая сквозной: MCP-клиент → сервер → канал → настоящий серверный код
  канала на C# (вместо Revit — тестовая заглушка); отказ по неверному токену; отказ записи при выключенном
  переключателе; очистка файла обнаружения от упавшего процесса;
- плагин проходит `claude plugin validate`.

Не проверено:
- **работа надстройки внутри Revit** — ни загрузка, ни одна команда Revit API не выполнялись;
- `install.ps1` не запускался (здесь нет Windows и PowerShell);
- расширение `.mcpb` не устанавливалось в Claude Desktop, манифест не проверялся официальным
  валидатором.

Первый запуск делайте на копии модели.
